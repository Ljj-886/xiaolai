# 卡通图标体系（自绘）

> 把原先的**系统 emoji**（📚💻🛏️…）替换为一套**自绘卡通图标**，
> 解决两个问题：① emoji 在 iOS / Android / 开发者工具里长相不一致；② emoji 的风格与贴纸风不搭。

---

## 一、图标规范（与 tabBar 图标同一套语言）

| 要素 | 规范 |
|---|---|
| 画布 | 120×120，**透明底** |
| 描边 | 深棕 `#3D2B1F`，宽度 8（**粗描边是卡通感的关键**） |
| 填充 | 扁平糖果色，**不用渐变、不用阴影** |
| 造型 | 圆角化、只保留必要结构线（结构性线条本身也是卡通感的一部分） |
| 生成 | `tools/gen_cartoon_icons.py`（Pillow，可重复生成、可微调参数） |

## 三、接线方式：WXS 映射，**不改数据库**

分类图标原本存在云数据库的 `categories.icon` 字段里（emoji）。**没有做数据迁移**，
而是用一个 WXS 模块做「key → 图标路径」映射，wxml 里直接调用：

```js
// utils/icon.wxs
var CAT = { book: 'cat_book', digital: 'cat_digital', /* … */ };
function cat(key) { return '/images/' + (CAT[key] || 'cat_other') + '.png'; }
module.exports = { cat: cat };
```

```xml
<wxs src="../../utils/icon.wxs" module="ico" />
<image class="cat-icon" src="{{ico.cat(item.key)}}" mode="aspectFit"/>
```

**好处**：零数据迁移、以后换图标只改 WXS 一处、云函数与数据库完全不用动。
（`key` 是稳定的分类标识，emoji 只是展示层的东西。）

## 四、配套的底托调整

图标**自带糖果色**了，所以底托改为**白底 + 深棕粗描边 + 大圆角**，让图标本身成为视觉主角；
同时保留上一轮的**轻微倾斜**（贴纸感）。

覆盖：首页分类宫格 `.cat-icon`、分类页左侧导航 `.left-icon`、「我的」四宫格 `.emoji`、
详情页操作栏 `.bar-icon .emoji`、发布/搜索小胶囊 `.pill-ico`。
