## 补充项：微信「用户隐私保护指引」接入（P0，差点漏掉的大坑）

**发现**：项目用了 5 类微信隐私接口共 8 个调用点——
`chooseAvatar`（login、edit-profile）、`chooseImage`（feedback/verify/publish/report）、
`chooseMedia`（chatroom/edit-profile）、`chooseLocation`（pickup）。
微信 2023.9 起要求接入隐私保护指引，否则审核卡住；而一旦开启
`__usePrivacyCheck__` 却不处理，这些接口会**直接失败**（选不了图、改不了头像、
选不了自提点）——属于"不做被拒、做错就崩"的双向风险项。

**实现（全局拦截，未改任何调用点）**：
- `app.json` 加 `"__usePrivacyCheck__": true`
- `app.js` 新增 `_initPrivacy()`，在 `onLaunch` 调用：
  注册 `wx.onNeedPrivacyAuthorization`，统一 `showModal` 让用户选，
  `resolve({event:'agree'|'disagree'})`；低版本基础库（无该 API）直接 return 不报错。
- **关键收益**：`onNeedPrivacyAuthorization` 是全局兜底，连 `open-type=chooseAvatar`
  这种无法前置拦截的按钮也覆盖，**8 个调用点一处兜住，零侵入**。

**自测** `test_privacy_guard.js` **9/9**：注册成功 / 同意 → agree / 拒绝 → disagree /
低版本无 API 时不抛异常且 cloud 仍初始化。

**回滚方法（重要）**：若真机发现选图异常，把 `app.json` 的
`"__usePrivacyCheck__"` 改成 `false` 即可，一行回退，不影响其他功能。

**前置依赖（必须用户做）**：`__usePrivacyCheck__` 依赖在 mp 后台
「设置 → 服务内容声明 → 用户隐私保护指引」中完成配置，否则微信端无指引可展示。
用户必须在提审前配好，并在指引里勾选本项目实际采集的类型：
用户信息（昵称/头像）、身份信息（姓名/学号/学校/学历/学籍证明）、
位置信息（自提点选点）、相册/文件（发布与认证图片）。

## 回滚：__usePrivacyCheck__ 接错时序导致登录页选头像/昵称静默失败（用户 01:07 反馈）

**用户反馈**：「这个功能用不了啊？你改代码的时候能不能不要修改他原来就正常的功能」并附登录页截图——sheet 已经展开（说明点过"登录"），但**头像/昵称点不动**（或授权登录失败）。

**根因**：开了 `app.json.__usePrivacyCheck__: true` 但**用户尚未在 mp 后台
「设置 → 服务内容声明 → 用户隐私保护指引」完成配置**。
- 微信端没有指引时，触发隐私接口（chooseAvatar / input type=nickname）会
  走 `wx.onNeedPrivacyAuthorization` 回调，期望开发者提供弹窗
- 我在 app.js 的 `_initPrivacy` 里弹了 showModal，但 `resolve({event:'agree'})`
  在 mp 后台无指引的语境下行为不可控（更糟的是基础库/微信服务器时序
  不一致时**接口直接静默失败**）
- 直接表现：头像栏点不动、昵称点不动、"授权并登录" 因 avatarUrl 永远为空被拦截

**教训（非常重要）**：
- `__usePrivacyCheck__` 是**要么全开要么全关**的开关，没"半启用"
- 它强依赖 mp 后台先配好《用户隐私保护指引》
- **正确的接法顺序**：先帮用户配好 mp 后台隐私指引 → 然后再打开
  `__usePrivacyCheck__` → 用户在真机首次触发隐私接口时微信会调
  `onNeedPrivacyAuthorization` → 我的 showModal 弹窗
- 我跳过了第一步直接开开关，破坏了原本正常的登录流程
- 用户的反馈「能不能不要修改他原来就正常的功能」非常合理
- **未来再次加此类开关前必须做**：① 先确认前置配置完成 ② 在真机验证
  "原来的功能" 仍可工作 ③ 提供 1 行回滚方案并提前告知

### 旧 cloud.js 的误判根因
旧版 `/utils/cloud.js` 只用 errMsg 字符串模糊匹配 `/not found|execution error|param|.../`，**完全不读 errCode**，且正则漏掉了实际形态：
- **"could not be found"**（"not" 与 "found" 中间有 "be"，不匹配 `/not found/`）
- **"execution fail"**（不是 "execution error"，不匹配）
- **"parameter could not be found"**（含 "parameter" → 居然能匹配 `/param/` —— 但 errMsg 包含的是 FunctionName **param**eter）—— 实际是歪打正着命中，但 raw 前缀包含 "param"，旧逻辑走「执行异常」
- **任何不匹配的情况都跌进默认** → 「网络异常，请稍后再试」——这就是用户截图看到的

### 升级：utils/cloud.js 按 errCode 精确判断
- 优先读 `errCode`：
  - `-501000` / `FUNCTION_NOT_FOUND` / `FunctionName ... could not be found` → 「云函数「X」未部署」
  - `-501003` / `FUNCTION_EXECUTE_ERROR` / `execution (error|fail)` → 「云函数「X」执行异常，请看开发者工具控制台」
  - `-502005` / `Db or Table not exist` / `502005` → 「数据库集合缺失」
  - `request:fail|timeout|network` → 「网络异常，请检查网络后重试」
  - `TOO_FREQUENT|too (many|frequent)` → 「操作太频繁，请稍后再试」
  - 其他 errCode → 「云函数「X」调用失败（错误码 N）」
- 兜底：把 errMsg 前 60 字展示给用户（不再笼统「网络异常」）
- `console.error` 完整打印 `{errCode, errMsg, stack}`，便于开发者工具/真机排查
