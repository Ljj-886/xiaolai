### 🐞 本轮发现并修复的真缺陷（我自己引入的）

上一轮给「我的」页加头像兜底时，我在 `fetch()` 开头写了「无条件清掉 avatarErr」。
**这是错的**：头像地址没变时清掉标记，会把 `<image>` 的 src 换回那个**已失败过的地址**，
而渲染层**不会对同一地址重发 error 事件** → `avatarErr` 永远为 false、兜底不再触发
→ **头像永久空白**（正是我原本要修的那类问题）。

**修复**：改为 `applyUser(me)`，**只有头像地址真的变了才清标记**。

> **通用原则（已写进技能）**：清「加载失败」标记**必须同时改变资源地址**；
> 只清标记不换地址，渲染层不会重新请求，兜底就会卡在「既无标记、也无图」的空白状态。

## 追加（15:44 → 01:29）：🐞 自定义 tabBar 盖住了发布按钮（我引入的回归，已修复）

**用户反馈：发布页的「立即发布」按钮不见了。**

**根因**：原生 tabBar 由系统渲染在 webview **之外**，页面里 `position:fixed; bottom:0` 的底栏
正好在它上方；而自定义 tabBar **在页面内**渲染（`fixed; bottom:0; z-index:999`），
把同样 `bottom:0` 的发布页底栏**整个盖住了**。

**排查**：`grep -rn "position: fixed" pages/*/*.wxss | grep -i bottom` 列出所有固定底栏，
对照 `app.json` 的 `tabBar.list` —— **只有 tab 页受影响**（非 tab 页不渲染 tabBar）。
全站 10 个有底栏的页面里只有 **publish** 是 tab 页。

**修复**：
1. `app.wxss` 加令牌 `--tabbar-h: 110rpx`
2. publish 的 `.bottom-bar` → `bottom: calc(var(--tabbar-h) + env(safe-area-inset-bottom))`
3. publish 的 `.page` 底部留白 → `230rpx + 安全区`（同时避开 tabBar 和底栏）

**验证**：截图确认按钮回到 tabBar 上方；5 个 tab 页 + detail/login 全部 0 报错。
**教训**：改 tabBar 这类"全站框架"的东西，回归不能只看渲染，
**必须专门检查布局层叠**（fixed/absolute/z-index）——功能没坏但按钮被盖住，用户看到的就是"按钮不见了"。
（已写进技能库。）
