## 二、测试中发现的两处「疑似问题」，经核实均为**预期行为**

排查这类误报比修 bug 更重要——避免以后被当成缺陷去改。

### 1. 打开「登录」页却跳到了「我的」

`pages/login/login.js` 的 `onShow`：

```js
if (wx.getStorageSync('cm_logged') === '1' && app.globalData.openid) {
  wx.navigateBack({ fail: () => wx.switchTab({ url: '/pages/mine/mine' }) });
}
```

已是登录态时主动返回上一页；若没有上一页（自动化里用 `reLaunch` 打开）则兜底跳「我的」。
**这是有意设计**，真实使用中登录页是 `navigateTo` 进来的，会正常返回。→ 测试已改为允许该替代路由。

### 2. 「我的商品 · 审核中」列表为空

经核对后台「商品管理」的待审数量同为 0 —— 说明待审商品已被你审核通过，**空列表是正确的**。
原断言把「列表非空」当成硬性要求，过于严格。→ 测试已区分
「必须非空」（如首页/分类/详情）与「必须存在数组、允许为空」（如审核中/收藏/订单）。

## 三、测试工程上的两点修正（都已写进技能库）

### 1. 写操作的成功判定要**看状态，不看响应码**

聊天页测试的清理步骤返回：

```
cloud.callFunction:fail -404006 empty poll result base resp.
```

但会话**确实已从列表消失**。`-404006` 是云调用偶发中断（响应丢失，函数其实已执行成功）。
所以断言必须基于**状态**（数据是否真的变了），否则会把成功判成失败。
→ 已改为「列表已消失 = 通过」，并保留一次重试。

### 2. `mp.screenshot()` 会重置 IDE 的页面栈

上一轮已踩到：截图夹在断言之间会导致后续读到**另一个页面**。
→ 本套测试把截图统一放在所有断言之后。
