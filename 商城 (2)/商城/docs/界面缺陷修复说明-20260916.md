## 一、用户直接反馈的问题

### 1.1 分类页左下角空白

**现象**：左侧分类栏「其他闲置」下方露出与右侧底色不一致的一块空白。

**根因**：左栏是 `scroll-view`，内容（10 项 × 约 200rpx ≈ 2000rpx）远超一屏可滚。
滚动到底时，`scroll-view` 的滚动区高度按内容算，超出视口的部分不会延伸背景色 ——
白色背景只在「内容高度」范围内生效，最后一项下方就露出了 `.page` 的米色底 `--bg #FFF9EE`。

**修复**（`pages/category/category.wxml` + `.wxss`）：

```html
<scroll-view class="left" scroll-y scroll-into-view="{{scrollIntoView}}" scroll-with-animation>
  <!-- 新增 .left-inner：负责「内容不足一屏时也撑满白色背景」 -->
  <view class="left-inner">
    <view wx:for="{{cats}}" wx:key="key" id="cat-{{item.key || 'all'}}" ...>
```

```css
.left-inner {
  padding-bottom: 40rpx;   /* 与 tabBar 留视觉呼吸，避免最后一项贴底 */
  min-height: 100%;        /* 关键：内容不足一屏也撑满，白底连成整片 */
  box-sizing: border-box;
  background: #fff;
}
```

> 注意 `padding-bottom` 必须放在**内容容器**（`.left-inner`）上，
> 直接放 `.left` 会在部分机型上被 `scroll-view` 的滚动区计算忽略。

**顺带修掉的两个隐患**：

| 隐患 | 原因 | 处理 |
|---|---|---|
| 选中项可能在视口外 | 10 项超一屏，点靠后的分类后看不出选了什么 | 加 `scroll-into-view`，切换时把选中项滚进视口 |
| 第 11 个分类起失去倾斜效果 | 原用 `:nth-child` 只覆盖前 10 项，且层级敏感易误伤 | 改为 JS 按索引算角度写内联 `style="--tilt: -3deg"` |

`scroll-into-view` 有个坑：「全部」的 key 是空串，`'cat-' + ''` → `cat-`（无效 id）。
统一用 `scrollIdOf = key => 'cat-' + (key || 'all')`，wxml 里 `id="cat-{{item.key || 'all'}}"`。

### 1.2 图片资源超 200K

**排查结果**：唯一超限的是根目录 `效果-商品卡片想要热度.png`（**261KB**），
且无任何代码引用 —— 是设计稿误留在项目根目录，会被打包进小程序包。

2. `project.config.json` 显式加一条 ignore 防护，避免以后有人再放回来

```json
{ "type": "file", "value": "效果-商品卡片想要热度.png" }
```

**顺带清理**：`.vscode` 目录加入 ignore。

### 1.3 「调试器 4」的 4 个报错

**排查方法**：写临时脚本连 automator，遍历 9 个主要页面挂 `console` + `exception` 事件收集日志。

**结果**：**error 0 条，warn 5 条**，其中最可疑的 4 条与「4」完全吻合：

```
warn  wx.getSystemInfoSync is deprecated.
      Please use wx.getSystemSetting/wx.getAppAuthorizeSetting/
      wx.getDeviceInfo/wx.getWindowInfo/wx.getAppBaseInfo instead.
```

**根因**：`components/nav-bar/nav-bar.js` 在 `attached` 里调 `wx.getSystemInfoSync()` 取状态栏高度。
**该组件被 21 个页面复用** —— 每进一个页面就刷一条警告，所以是 4 条（当次遍历到的页面数）。

**修复**：

```js
// 改前
const sys = wx.getSystemInfoSync();
this.setData({ statusBarHeight: sys.statusBarHeight || 20 });

// 改后（最小粒度新 API，基础库 2.20.1+；项目 libVersion=3.4.6，远高于要求）
const win = wx.getWindowInfo();
this.setData({ statusBarHeight: win.statusBarHeight || 20 });
```

> 刻意**不做旧 API 兜底** —— 留一条回退路径等于给废弃 API 留后门，
> 下次扫描还会判定为未清理。万一新 API 不存在，catch 里保留 `data` 默认值 20 即可。

同类 API 的替换对照（供后续参考）：

| 用途 | 旧 API | 新 API |
|---|---|---|
| 窗口 / 状态栏尺寸 | `wx.getSystemInfoSync()` | `wx.getWindowInfo()` |
| 机型 / 平台 | 同上 | `wx.getDeviceInfo()` |
| 基础库 / 主题 | 同上 | `wx.getAppBaseInfo()` |
| 授权状态 | 同上 | `wx.getAppAuthorizeSetting()` |

## 二、全项目排查额外发现（4 类）

按要求「顺便再看看小程序还有什么问题」，做了静态 + 结构级排查，另发现 4 类问题。

### 2.1 自定义 tabBar 高度口径不统一 ⭐

**问题**：`--tabbar-h` 全局变量写的是 `110rpx`，但按 `custom-tab-bar/index.wxss` 逐条累加**实测是 114rpx**：

```
边框 top            4rpx
.tab-item padding-top   14rpx
.tab-ico-wrap 高        46rpx
.tab-item gap            6rpx
.tab-txt 行高 (20×1.2)  24rpx
.tab-item padding-bottom 16rpx
边框 bottom          4rpx
────────────────────────────
合计               114rpx  = 57.0px @375px 宽
```

再叠加未读角标 `top: -14rpx` 的上溢，取 **120rpx** 才够。

更严重的是：**4 个页面把 `110rpx` 硬编码进 `calc()`**，只有 `publish` 用了变量。
一旦 tabBar 改样式，硬编码的地方不会跟着变。

**修复**：
- `--tabbar-h` 改为 `120rpx`，并在注释里写清推导过程与「改 tabBar 必须同步」
- 4 处硬编码全部收口到 `var(--tabbar-h)`

| 文件 | 改前 | 改后 |
|---|---|---|
| `pages/category/category.wxss` | `calc(100vh - 110rpx - …)` | `calc(100vh - var(--tabbar-h) - …)` |
| `pages/chat/chat.wxss` | `calc(110rpx + …)` | `calc(var(--tabbar-h) + …)` |
| `pages/index/index.wxss` | `calc(110rpx + …)` | `calc(var(--tabbar-h) + …)` |
| `pages/mine/mine.wxss` | `calc(110rpx + …)` | `calc(var(--tabbar-h) + …)` |

### 2.2 聊天室面板与输入框错位 ⭐ 真 bug

**问题**：`.plus-panel` / `.emoji-panel` 的定位写死 `bottom: calc(100rpx + env(safe-area-inset-bottom))`，
但 `.ipt` 是 **`auto-height` 的 textarea（40~240rpx）**，用户换行后 `.input-bar` 会明显变高。

- 单行时：input-bar 实测 96rpx，面板 bottom 100rpx → **悬空 4rpx 露缝**
- 多行时：input-bar 涨到 150rpx+，面板 bottom 仍是 100rpx → **面板被输入框盖住**

**修复**：改为实测输入栏真实高度，写进 CSS 变量：

```js
// chatroom.js — onShow 与每次 onInput 后重测
_measureInputBar() {
  wx.nextTick(() => {
    wx.createSelectorQuery().select('.input-bar')
      .boundingClientRect(rect => {
        if (!rect || !rect.height) return;
        let rpx = rect.height;
        try {
          const w = wx.getWindowInfo().windowWidth || 375;
          rpx = Math.ceil(rect.height * 750 / w);
        } catch (e) { rpx = Math.ceil(rect.height * 2); }
        if (rpx === this._inputH) return; // 高度没变 → 不重复 setData
        this._inputH = rpx;
        this.setData({ inputH: rpx });
      }).exec();
  });
}
```

```html
<view class="page" style="--input-h: {{inputH || 96}}rpx">
```

```css
.plus-panel, .emoji-panel {
  bottom: calc(var(--input-h) + env(safe-area-inset-bottom));
}
```

### 2.3 三个页面的 `.page` 完全没有样式 ⭐ 真 bug

**问题**：26 个页面里 23 个各自写了 `.page`，但 `agreement` / `credit` / `privacy`
**三个页面完全没写**，`app.wxss` 也没有 —— 这三个长内容页的底部**直接贴屏幕底边**，
被全面屏的 Home 指示条压住。

**根因**：`.page` 这个语义在 23 个文件里各写一份，漏掉一个就出 bug。
这是典型的「该有全局基线却靠复制粘贴维持」的问题。

**修复**：在 `app.wxss` 加全局基线，页面只覆写差异：

```css
.page {
  min-height: 100vh;
  box-sizing: border-box;
  padding-bottom: env(safe-area-inset-bottom);
}
```

> 页面级 `.wxss` 的 `.page` 规则优先级更高，已有覆写全部保持原样生效。

**顺带修掉**：`login.wxss` 写 `padding: 32rpx`，把全局基线的 `padding-bottom` 整条覆盖掉
→ 登录按钮贴到 Home 指示条。改为 `padding: 32rpx 32rpx calc(32rpx + env(safe-area-inset-bottom))`。

### 2.4 孤儿 class：`tab-pill`

**问题**：`custom-tab-bar/index.wxml` 里长期留着一个 `<view class="tab-pill">`，
但**全项目没有任何 `.tab-pill` 样式** —— 改版残留，多包一层无用节点且误导后人。

**修复**：就地删掉该包裹层。`.tab-item` 本身已是 `flex-direction: column`，
节点结构简化为 `item > ico-wrap + txt`。

## 六、这批问题的共性教训

1. **同一个语义别在 N 个文件里各写一遍。**
   `.page` 写 23 遍漏 3 个、`--tabbar-h` 写 5 处只 1 处用变量 —— 都是同一个病。
   有全局语义的（页面基线、组件高度）就该有一份全局基线 + 一条断言。

2. **写死的数字要和真实渲染量对账。**
   `100rpx` 面板定位 vs 实测 `96rpx` 输入栏、`110rpx` 变量 vs 实测 `114rpx` tabBar ——
   两处都是「凭感觉写数字」，两处都错了。能测就测（`boundingClientRect`），
   不能测就把推导过程写进注释。

3. **复用度高的组件，一行废弃 API 会被放大成 N 条告警。**
   nav-bar 被 21 个页面复用，一行 `getSystemInfoSync` 就成了「调试器 4 个报错」。
   组件里的 API 调用要格外保守。

4. **修复要留下能主动报警的断言，而不是只改完事。**
   本轮 21 条新断言里，最有价值的是「硬编码 110rpx 已清零」和
   「覆写 .page 的页面都处理了底部」—— 它们能在下次有人复制粘贴时立刻拦住。
