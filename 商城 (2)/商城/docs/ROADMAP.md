# 校园集市 · 多校上架完善路线图（v2：个人主体版）

> 决策基线（已与用户确认）：
> - **主体：个人**。仅用于方便学生之间交易，非营利。
> - **交易**：纯面交·虚拟订单（不接微信支付，规避支付合规）。
> - **多校**：严格各校独立、互不可见（字段级 `campus` 隔离，全集合覆盖）。
> - 参考标杆：闲鱼校园圈 / 转转 / 多抓鱼 的校园版 PRD；微信小程序运营规范。

## ⚠️ 个人主体的上架现实（最重要的一条）
微信规则：**个人主体小程序不能选电商/交易类目，不能接入微信支付，也不能从事经营性互联网信息服务**（那需要 ICP 证，个人无法取得）。所以按「二手交易平台」正式交易类目提审，个人主体**大概率被拒**。

可行路径（按推荐度）：
1. **定位为「校园闲置信息交流 / 校内联系撮合」工具（推荐）**：不出现「交易 / 支付 / 下单 / 订单」等强交易词，改用「发布闲置 / 留言约面交」；类目选「工具-信息查询」或「校园服务」类。内容安全照常接。这是个人主体最可能过审的方式。
2. **转个体工商户**：以后想正经做平台、收佣金、铺多校，再注册个体户（营业执照+ICP备案，约 1–2 个月），改选「商家自营-二手用品」类目。合规但重。
3. **小范围不上架**：开发者工具预览 + 体验成员二维码，仅限同学使用，绕开审核。

无论走哪条，**内容安全 API、隐私政策、举报/反馈入口**都是硬要求（注：个人主体无法接入微信客服，故"客服"需用内置表单实现，而非微信客服系统）。

## P0 上架合规硬门槛
1. **内容安全 API（msgSecCheck/imgSecCheck）—— 已实现**：见 `cloudfunctions/seccheck`（需在云开发控制台开通「内容安全」能力，否则优雅降级放行）。
2. **举报/反馈入口（内置表单，非微信客服）**：`mine`/设置/商品详情页加「举报」「反馈」入口，提交到云函数入库（`feedback`/`reports` 集合），你后台可查 + 人工处理。个人主体无法接入微信客服（`open-type="contact"` 与 `wx.openCustomerServiceChat` 均要求企业/组织主体），所以不能用微信客服，改内置表单。**审核真正要看的是"有举报入口 + 响应承诺"，不是必须用微信客服系统。**
3. **隐私政策独立页 + 采集前明示同意**：现有 `agreement` 页拆分为「用户协议」+「隐私政策」，注册/认证前弹窗明示。
4. **定位与文案调整**：去「交易/支付」字眼，类目选工具/信息查询类。

## P1 严格多校独立架构
5. 全集合 `campus` 隔离（goods 已做；orders/conversations/reports/reviews/favorites/verify 补齐；严格独立 = 连跨校浏览入口都不留）。
6. 校区管理员 RBAC（school_admin 只管本校）。
7. 学校开通状态机（pending/active/disabled）。
8. 跨校数据隔离审计（grep 所有 `where` 确认无遗漏）。

## P2 信任与体验
9. 信用可视化（蓝V / 交易数 / 好评率）。
10. 学信网认证落地（管理员人工比对截图，无需在线验证码字段）。
11. 求购专区 / 收藏 UI / 订单订阅消息 / 毕业季专场 / 分享海报 / 敏感词过滤。
12. 安全遗留（限流、wipeGoods 二次确认、setAdmin 审计）。

## P3 体验打磨
13. 骨架屏 / 错误重试 / 空状态 / 发布草稿 / 键盘避让。

## 参考标杆要点（来自调研）
- 闲鱼校园圈：同校优先 + LBS + 担保交易（你用面交替代担保，规避支付合规）。
- 转转：官方验机/验货信任体系（你用学信网认证 + 信用分替代）。
- 多抓鱼：垂直品类 + 标准化成色（你的 CONDITIONS 已覆盖）。
- 多租户架构：字段级隔离（tenant_id/campus）+ RBAC 两级权限（生源宝模式）。
- 微信审核红线：UGC 必接内容安全；需举报/反馈入口（个人主体无法接微信客服，用内置表单）；隐私政策明示；个人主体禁经营电商。
