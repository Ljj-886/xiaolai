# 视觉风格改造：手绘贴纸风（Sticker Doodle）

> 你选定的方案 **E · 手绘贴纸风**，已落地并在真机验证通过。

---

## 一、风格定义（设计令牌）

| 令牌 | 值 | 说明 |
|---|---|---|
| `--bg` | `#FFF9EE` | 奶油底（原 `#F5F6F8` 冷灰） |
| `--ink` | `#3D2B1F` | 深棕 —— **描边色 + 主文字**（原 `#1A1A1A`） |
| `--ink-2` / `--ink-3` | `#8A6F55` / `#B39B80` | 次要/三级文字（原 `#666` / `#999`） |
| `--primary` | `#E8542F` | 珊瑚橙（原 `#FF6B35`，调深调暖） |
| `--line` | `#E8DCC6` | 暖色分隔线（原 `#ECECEC`） |
| `--radius` | `20rpx` | 圆角 |
| `--shadow` | **`none`** | **贴纸风不使用阴影** |

**三个核心手法**：
1. **描边代替阴影** —— 卡片用 `4rpx` 深棕描边，**右下加粗到 `8rpx`** 做出贴纸的"翘边"体积感；
2. **配色收敛** —— 珊瑚橙只用于价格 / 主按钮 / 选中态；
3. **去渐变** —— 品牌渐变一律拍平为纯色，保证扁平贴纸质感。

## 六、自定义 tabBar（药丸选中态）✅

原生 tabBar 只支持改文字/图标颜色，做不出效果图里的**药丸高亮 + 描边**。已改为自定义 tabBar。

### 改动

| 文件 | 改动 |
|---|---|
| `custom-tab-bar/index.js｜json｜wxml｜wxss` | **新增组件**：奶油底 + 顶部深棕描边；选中项珊瑚橙药丸底 + 珊瑚橙文字 + 选中态图标；未读角标自绘（`99+` 封顶） |
| `app.json` | `tabBar.custom = true`（保留 `list` 与配色作为兜底） |
| `app.js` | 新增 `syncTabBar(index)`（同步选中项 + 未读数）；**`setUnreadBadge()` 重写** |
| 5 个 tab 页 `onShow` | 各加一行 `app.syncTabBar(n)` 告知自己是第几个 tab |
| 5 个 tab 页 `.page` | 底部留出 `110rpx + 安全区`（自定义 tabBar 是 fixed 定位，不再自动占位） |

### ⚠️ 自定义 tabBar 的两个必须自己处理的代价

1. **`wx.setTabBarBadge` 在 custom 模式下失效** —— 未读角标必须自己在组件里渲染。
   已把 `app.setUnreadBadge(n)` 从「调原生 API」改为「把未读数推给组件」，
   并在 `globalData` 存一份，供组件首次渲染直接读取。
2. **选中态不再自动维护** —— 每个 tab 页都要在 `onShow` 里主动同步。

### 🐞 追加修复：自定义 tabBar 盖住了发布页的「立即发布」按钮

**现象**：改成自定义 tabBar 后，发布页最后的发布按钮**整个消失**。

**原因**：原生 tabBar 由系统渲染在 webview **之外**，页面里 `position:fixed; bottom:0` 的底栏
正好在它上方；而自定义 tabBar 是**在页面内**渲染（`fixed; bottom:0; z-index:999`），
把同样 `bottom:0` 的发布页底栏**整个盖住**。

**影响面**：全站 10 个有固定底栏的页面里，**只有发布页是 tab 页**，所以只有它出问题
（非 tab 页不渲染 tabBar，底栏照旧贴底）。

**修复**：
1. `app.wxss` 新增令牌 `--tabbar-h: 110rpx`；
2. 发布页 `.bottom-bar` → `bottom: calc(var(--tabbar-h) + env(safe-area-inset-bottom))`；
3. 发布页 `.page` 底部留白 → `230rpx + 安全区`（同时避开 tabBar 与底栏）。

**验证**：截图确认按钮回到 tabBar 上方；全量 **26/26 页** + **59/59 功能**，均 0 报错。

> **经验**：改 tabBar 这类「全站框架」的东西，回归不能只看"渲染是否正常"，
> **必须专门检查布局层叠**（fixed / absolute / z-index）——
> 功能没坏但按钮被盖住，用户看到的就是"按钮不见了"。

### 本轮抓到的两个真 bug

| 问题 | 原因 | 修复 |
|---|---|---|
| 「消息」tab 高亮错位（显示首页） | `chat.js` 里的 `const app = getApp()` 写在 **`open()` 函数内部**，`onShow` 里的 `app` 实际未定义 → 抛错 | 补**模块级** `const app = getApp()`，删掉被遮蔽的重复声明 |
| 组件挂载时高亮可能错位 | 在 `attached()` 里用 `getCurrentPages()` 反推选中项，而挂载时当前路由可能仍是上一页 | 反推时机改为 `pageLifetimes.show`（页面显示时回调） |

### 验证

`tools/verify_custom_tabbar.js` + `tools/verify_tabbar_badge.js`：

- 5 个 tab 页选中态**全部正确**（首页 0 / 分类 1 / 发布 2 / 消息 3 / 我的 4）
- 未读角标：`setUnreadBadge(7|0|123)` → 组件 `unread` 同步为 7/0/123，`99+` 渲染正确（见截图）
- 全量回归：**26 页 26/26**、**59 项功能 59/59**，**均为 0 报错 0 警告**

> 说明：验证过程中出现过几次 `timeout waiting for automator response`，
> 是自动化工具在连续多次操作后退化所致（同一断言单独跑即通过），**非应用问题**。
