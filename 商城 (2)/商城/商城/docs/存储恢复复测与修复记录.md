## 二、本轮发现并修复的一个真实缺陷（我自己引入的）

### 问题：无条件清除「图片失败标记」会让头像**永久空白**

我在上一轮给「我的」页加头像兜底时，在 `fetch()` 开头写了一句：

```js
// 本意：重新拉取时清掉失败标记，让恢复后的头像有机会重新加载
if (this.data.avatarErr) this.setData({ avatarErr: false });
```

**这是错的**。当头像地址**没有变化**时，清掉标记会把 `<image>` 的 `src` 换回那个**已经失败过的地址**，
而渲染层通常**不会对同一地址重发 `error` 事件** → `avatarErr` 永远保持 `false`，
兜底也不再触发 → **头像永久空白**（正好是我原本要修的那类问题）。

**复现**：逐项测试时实测 `avatarErr=false`（而当时图片确实加载失败）——被测试抓到了。

### 修复：只有图片地址**真的变了**才清标记

```js
applyUser(me) {
  const next = (me && me.avatarUrl) || '';
  const changed = next !== this._lastAvatar;
  this._lastAvatar = next;
  const patch = { user: me, logged: true };
  if (changed && this.data.avatarErr) patch.avatarErr = false;  // 仅在换人/换头像时重试
  this.setData(patch);
}
```

**通用原则**：**清「加载失败」标记必须同时改变资源地址**；只清标记不换地址，
渲染层不会重新发起请求，兜底就会卡在「既没标记、也没图片」的空白状态。
