# 发布后商品去哪了？—— 发布与审核流程说明

## 先给结论

**发布是成功的，数据也写进数据库了**，商品并没有丢。只是它进入了「**待审核**」状态，
而首页只展示已上架的（`onSale`）商品 —— 所以你不会在首页看到它。

真实数据（排查当时）：

```
goods 总数 12：onSale 7 / pending 2 / off 2 / sold 1
待审核 2 条：
  09-11 11:37   "32313"      status=pending
  09-11 11:36   "测试封面"    status=pending
```

这两条正是刚发布的商品，它们**确实存在**，只是卡在待审核。

---

## 完整状态流转

```
用户点「发布」
     ↓
goods.publish 写入数据库
     ↓
status = 'pending'  ← 待审核（此时只有「我的商品 · 审核中」能看到）
     ↓
管理员在后台点「通过上架」
     ↓
status = 'onSale'   ← 已上架（此时才会出现在首页 / 分类 / 搜索）
```

驳回分支：管理员点「驳回」→ `status = 'off'`，并记录 `offReason`（驳回原因）。

| 状态 | 含义 | 谁能看到 |
|---|---|---|
| `pending` | 待审核 | **仅自己**（我的商品 → 审核中）+ 管理员后台 |
| `onSale` | 已上架 | 所有人（首页 / 分类 / 搜索） |
| `sold` | 已售出 | 自己 + 他人主页 |
| `off` | 已下架 / 被驳回 | 自己 + 他人主页 |
| `reserved` | 已预订 | 自己 + 他人主页 |

---

## 怎么把商品上架

**入口：小程序 →「我的」→ 管理后台 →「商品管理」**

「商品管理」默认就停在「**待审核**」tab，每条商品下面有：

- **通过上架** → 商品立刻出现在首页
- **驳回** → 需填写驳回原因（用户会在商品页看到）

---

## 本次修复：让「待审核」这个状态**看得见**

### 问题

之前的状态是：
1. 发布成功后只弹一句「发布成功」，然后跳回首页；
2. 但商品是 `pending`，首页不显示；
3. 而「我的商品」的 tab 只有 **在售 / 已售 / 已下架** —— **`pending` 没有任何入口**；
4. 商品卡片的角标文案表 `STATUS_GOODS` 里**没有 `pending` 映射** → 即使渲染出来也是空白角标。

结果就是：**提示发布成功，但哪里都找不到商品** —— 很容易被误判成「发布失败 / 数据没保存」。

### 修复内容

| 文件 | 改动 |
|---|---|
| `pages/sold/sold.js` | 「我的商品」自己视图新增「**审核中**」tab（看他人主页时不显示） |
| `pages/sold/sold.wxml` | 审核中页顶部加说明条；空状态文案按 tab 区分 |
| `pages/publish/publish.js` | 发布成功后改为弹「**已提交审核**」说明，并直接跳到「我的商品 · 审核中」，让你立刻看到刚提交的商品 |
| `utils/util.js` | `STATUS_GOODS` 补 `pending: { text: '审核中' }`（此前角标是空白） |
| `pages/admin-goods/admin-goods.js` | 后台沿用「待审核」措辞，与 tab 名保持一致 |

## 可选：是否保留「先审后发」

当前是**先审后发**（`status: 'pending'`，需管理员在后台点通过）。

- **保留的好处**：符合 UGC 内容安全要求，违规内容不会先暴露给用户；图片/文字已有异步安全检测，审核流是最后一道人工闸门。
- **代价**：每发一件商品都要去后台点一次「通过上架」；如果只有你自己用，会比较繁琐。

如果希望改成**先发后审**（发布即 `onSale`，违规内容靠事后巡检/举报下架），
只需把 `cloudfunctions/goods/index.js` 里 publish 的 `status: 'pending'` 改为 `'onSale'`，
并相应调整「审核中」tab 的展示（可保留，用于显示被驳回的商品）。
