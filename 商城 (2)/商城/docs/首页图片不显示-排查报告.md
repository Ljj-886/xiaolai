# 首页商品图片不显示 —— 排查报告与修复

## 一、结论（先说最重要的）

**这不是代码 bug，是腾讯云/微信云开发账号欠费，云存储的读取被停服了。**

所有云存储文件（商品图、用户头像）的请求都返回：

```
HTTP 451 UnavailableForLegalReasons
<?xml version='1.0' encoding='utf-8' ?>
<Error>
  <Code>UnavailableForLegalReasons</Code>
  <Message>Due to your account is arrears, it is unavailable until you recharge.</Message>
  <Resource>/goods/wxu-1789126543154_0_6oxz.jpg</Resource>
</Error>
```

**解药是把账号欠费结清（充值）**，代码侧无法绕过。

---

## 二、排查过程（先排除代码原因）

按「接口数据 → 图片路径 → 加载逻辑」逐层查，得到一个与代码无关的结论。

### 第 1 步：接口数据是否正常？ → 正常

`goods.list` 返回 5 条，`cover` 都是合法的 https 临时链接，且都带 `imageMogr2` 参数：

```
#0 31eb60 cover=https://636c-cloud1-...tcb.qcloud.la/... 带Mogr2=true
#3 acb0e6 cover=(空，该商品本来就没图)
```

**接口层没有问题。**

### 第 2 步：图片路径是否可取？ → **取不到，HTTP 451**

对封面发真实请求，全部返回 `451`（而不是路径错误会有的 404、或签名过期会有的 403）。

### 第 3 步：定性 —— 是单个文件还是整桶？ → 整桶

| 请求对象 | 结果 |
|---|---|
| 商品图（带 `imageMogr2`） | **451** |
| 商品图（去掉 `imageMogr2`，用原始链接） | **451** |
| 商品图（不带任何签名参数） | 403（预期，没签名本来就该拒） |
| **我的头像** | **451** |
| **另一件商品图** | **451** |

**不同目录（`/goods/`、`/avatar/`）、不同文件全部 451** → 不是某个文件的问题，是**整个存储服务的读取被停用**。

### 第 4 步：影响面边界

| 能力 | 状态 |
|---|---|
| 云函数调用 | ✅ 正常 |
| 云数据库读写 | ✅ 正常 |
| `getTempFileURL` 换链 | ✅ 正常（能拿到链接，只是链接指向的内容取不到） |
| **上传文件 `uploadFile`** | ✅ 正常 |
| **读取图片（HTTP/CDN）** | ❌ **全部 451** |
| `deleteFile` | ✅ 正常 |

即：**写能进、读不出来**。所以所有文字功能正常，所有图片显示不出来。

---

## 三、代码侧仍然做的改进（降级体验 + 自愈）

虽然根因是外部服务，但「图片取不到时界面表现如何」是代码的责任。排查中发现两处不足，已修复。

### 改进 1：补齐图片失败兜底（此前只有列表卡片有）

`goods-card`（首页/分类/搜索/收藏/我的商品）此前已有兜底；但**详情页大图没有** ——
存储故障时「列表有占位图、点进详情却是整块留白」，体验不一致。

| 位置 | 修复前 | 修复后 |
|---|---|---|
| 商品详情 · 大图 | 留白 | 回退 `goods-cover-default.png` 占位图 |
| 商品详情 · 卖家头像 | 留白（仅有空值兜底，无失败兜底） | 回退默认头像 |
| 聊天页 · 对端头像 | 留白 | 回退默认头像 |
| 聊天页 · 顶部商品封面 | 有值兜底，无失败兜底 | 回退占位图 |
| 聊天页 · 图片消息 | 空白气泡 | 显示「图片加载失败」 |
| 「我的」· 头像 | 留白 | 回退默认头像 |

### 改进 2：加载失败可**自愈**（新增一次重试）

此前 `goods-card` 加载失败后会**一直停在占位图**，即使服务恢复也不会自愈
（要等用户手动刷新列表）。

现在：失败 → 先降级占位图（绝不留白）→ **5 秒后自动重试一次**（附时间戳参数绕过失败缓存）。
只重试一次，避免服务持续故障时反复发请求。

> 重试是「有界」的：重试再失败即停止，不会死循环。

## 四、验证结果（真机）

因为当前正好处于存储停服状态，**这是天然的失败场景**，可直接验证兜底逻辑。

| 验证项 | 结果 |
|---|---|
| 详情页大图失败标记（`imgErr=["0"]`）→ 已回退占位图 | ✅ |
| 「我的」头像失败标记（`avatarErr=true`）→ 已回退默认头像 | ✅ |
| 详情页截图：显示占位图而非留白 | ✅ 见截图 |
| 聊天页（改动后模板仍正常渲染） | ✅ 8 / 8 |
| **全页面模块测试 26 页** | ✅ **26 / 26**，JS 报错 **0 条** |
| **全功能测试（47 接口 + 12 流程）** | ✅ **59 / 59**，JS 报错 **0 条** |

### 调试器（控制台）检查

按要求每步之后都检查了控制台。结果：

- **JS 错误：0 条**（26 页 + 59 个功能项全部为 0）
- 警告：仅在「图片加载失败」处出现（列表页 5~10 条/页）——
  这正是欠费导致的 451，属于**预期表现**，不是代码缺陷

## 六、遗留与建议

- **`/probe/` 目录**：排查过程中用云存储上传过一个 40×40 的探针小图，**已删除**。
- **欠费期间的行为预期**：所有图片位置显示占位图（商品）或默认头像（用户），
  文字、发布、审核、聊天、订单等功能完全可用。
- **建议开启余额提醒**：云存储停服会让「图片全部消失」但**接口一切正常**，
  这类故障很容易被误判成代码 bug（本次即如此）。建议在腾讯云控制台设置余额预警。
