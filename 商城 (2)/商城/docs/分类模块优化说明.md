## 二、根因：没有单一分类数据源

改动前，分类的 key / 中文名 / 图标 / 图标文件名映射散落在 **7 个文件**：

| 文件 | 承担的角色 |
|---|---|
| `utils/constants.js` | `CATEGORIES` 数组（key + name + emoji） |
| `utils/icon.wxs` | WXS 内又硬编码一份 key → 图标文件名 |
| `pages/category/category.js` | 自写 `CATEGORIES.find(c => c.key === key).name` |
| `pages/order/order.js` | 又写一遍 `function catName(key)` |
| `pages/order-detail/order-detail.js` | 又写一遍 `CATEGORIES.find(...)` |
| `pages/sold/sold.js` | 又写一遍 `map(c => ({key, name}))` |
| `pages/detail/detail.wxml`、`pages/admin-goods/admin-goods.wxml` | **完全没映射**，直接渲染英文 key |

后果：新增/改一个分类要改 7 处；漏改的地方就把 `book`、`digital` 显示给用户（问题 2、3 就是这么来的）。

### 解法：`utils/categories.js` 作为唯一数据源

新增 `utils/categories.js`，提供：

| 导出 | 用途 |
|---|---|
| `CATEGORIES` | 分类定义表（key/name/icon），**唯一副本** |
| `ICON_FILE` | key → 图标文件名 |
| `catName(key)` | key → 中文名（兼容历史脏数据：写入中文名的、未知 key 都能给出可读结果） |
| `catIcon(key)` / `catEmoji(key)` / `catOf(key)` | 图标路径 / emoji / 定义对象，非法 key 统一兜底到「其他闲置」 |
| `catOptions(label)` | 带「全部」项的分类列表（筛选条常用） |
| `isCatKey(key)` / `CATEGORY_KEYS` | 合法性判断与全量 key（服务端校验复用） |

`utils/constants.js` 改为从新模块转发（保持既有 import 不破坏），
并把「需要中文名一律用 `catName(key)`，不要各页面再写 `CATEGORIES.find(...)`」写进注释。

**收口结果**（改后全局核查）：

```
① 仍从 constants 引入 CATEGORIES 的地方 → 无
② 仍自己写 CATEGORIES.find 的地方      → 无（仅 categories.js 内部实现）
③ 仍直接渲染 item.category 的地方      → 无（已全部改为 categoryText）
```

### 防漂移：一致性校验脚本

`utils/icon.wxs` 因为 wxml 内联表达式无法 `require` JS 模块，必须保留一份只读副本。
新增 `scripts/check-category-sync.js` 做四方校验：

```
① ICON_FILE 每个 key 在 icon.wxs 里都有且文件名一致
② icon.wxs 没有多余 key（删分类后的残留）
③ 每个图标素材 images/cat_xxx.png 真实存在
④ 分类数与图标映射数相等
```

运行：

```bash
node scripts/check-category-sync.js
# ✓ 分类映射一致性校验通过：10 个分类的 key / 图标 / 素材三方一致
```

退出码 0/1，可挂到提交前检查。

## 三、分类页四态修复细节

### 改前（两组独立链，会同时渲染）

```html
<view wx:if="{{!loading && loadError}}">…加载失败/重试…</view>
<view wx:elif="{{!loading && list.length === 0}}">…暂无商品…</view>
<view wx:if="{{loading}}">加载中…</view>          <!-- 新链开始 -->
<view wx:elif="{{hasMore}}">点击加载更多</view>   <!-- loadError 时也会命中！ -->
<view wx:elif="{{list.length > 0}}">没有更多了</view>
```

`loadError` 为真时 `loading=false` → 第二个 `wx:if` 不成立 → 落到 `wx:elif="{{hasMore}}"`，
而 `hasMore` 还停留在上一次成功请求的值 → **「加载失败/重试」与「点击加载更多」并存**。

### 改后（首屏四态互斥 + 列表内翻页态独立）

```html
<!-- 首屏四态单链互斥 -->
<view wx:if="{{loading && !list.length}}" class="loading">加载中…</view>
<view wx:elif="{{loadError && !list.length}}"><empty … retry/></view>
<view wx:elif="{{!list.length}}"><empty … 暂无商品/></view>
<block wx:else>
  <!-- 已有列表时，底部翻页区单独一链 -->
  <view wx:if="{{loading}}" class="loading">加载中…</view>
  <view wx:elif="{{loadError}}" class="loading err" bindtap="retry">加载失败，点击重试</view>
  <view wx:elif="{{hasMore}}" class="loading" bindtap="loadMore">点击加载更多</view>
  <view wx:else class="loading">— 没有更多了 —</view>
</block>
```

配套：新增 `.loading.err` 样式（主色 + 下划线），让「点击重试」看起来是可点的。

### 请求令牌 + 节流

切分类会产生「旧请求在途、新请求已发」的竞态，旧请求后返回会把上一个分类的商品覆盖回来
（表现为「点了没反应」或「列表串了」）。加入：

- **请求令牌**：`fetchList` 每次自增 `_reqToken`，只有令牌最新的请求才允许 `setData`，过期结果静默丢弃。
- **切换节流**：`SWITCH_THROTTLE_MS = 200`，间隔内的连点直接丢弃。

## 四、云函数改动

### `goods`

| 位置 | 改动 |
|---|---|
| `decorate()` | 每个商品补 `categoryText`（中文名），列表/详情统一生效 |
| `publish()` | `category` 增加**白名单校验**，脏 key 直接拒绝并提示 |
| `update()` | 同上 |

**为什么加白名单**：此前 `publish/update` 对 `category` 完全不做校验，客户端传什么就存什么。
脏 key（拼错、中文名、任意字符串）会静默入库，后果是**商品在分类页永远搜不到**
（筛选按 key 精确匹配），且后台无法归类。

### `admin`

`listGoods()` 每个商品补 `categoryText`。云函数部署时只打包本目录、无法 `require` 小程序端模块，
故内联一份 `CATEGORY_MAP` 副本，由 `scripts/check-category-sync.js` 保证与前端一致。

### 附：分页改游标式的建议

当前 `goods.list` 用 `skip((p-1)*size).limit(size)`。深翻页时 `skip` 需先扫描并丢弃前 N 条，
第 10 页（skip=180）在万级数据下明显劣化。建议改游标式：

```js
// 客户端带上上一页最后一条的 createdAt
if (cursor) where.createdAt = _.lt(cursor);
query = query.orderBy('createdAt', 'desc').limit(size);
```

本次未动此逻辑（改动面涉及前后端分页协议，需单独评估），仅作记录。

## 六、⚠️ 架构发现：`categories` 集合只写不读

排查中发现 `cloudfunctions/admin/index.js` 存在 `COL_CAT = 'categories'` 常量，
`admin.init` 会写入 10 个分类（带 `sort` 字段）：

```js
const cats = [
  { key: 'book', name: '教材书籍', icon: '📚', sort: 1 },
  ...
];
for (const c of cats) {
  const ex = await db.collection(COL_CAT).where({ key: c.key }).limit(1).get();
  if (!ex.data || !ex.data.length) await ensureAdd(COL_CAT, c);
}
```

**但全项目没有任何地方读取这个集合** —— 前端分类完全依赖硬编码的 `CATEGORIES`。
即：库里那份 `categories` 数据是**只写不读的死数据**。

这意味着项目里并存着**两条分类数据源**，且它们可能已经漂移（例如有人改了 `admin.init`
的 `cats` 却忘了改 `utils/categories.js`，或反之）。

**本次未改变这一架构**（属于方案级决策，需你确认方向）：

| 选项 | 说明 | 代价 |
|---|---|---|
| A. 保持硬编码 | 现状。分类固定，改分类需发版 | 无法后台动态增删分类 |
| B. 改读数据库 | 新增 `admin.listCategories` / 前端 `getCategories()` 带缓存，`admin.init` 保证初始数据 | 需处理缓存失效、首次加载、旧客户端兼容 |
| C. 硬编码为准 + 删死数据 | 明确 `utils/categories.js` 是唯一源，删掉 `categories` 集合与 `admin.init` 里的写入 | 需确认没有别处（如运营脚本）依赖它 |

**建议选 C 起步**（消除歧义成本最低），等确有「后台动态加分类」的需求再走 B。

### 7.4 踩过的 automator 坑（新增，补入 MEMORY）

`MEMORY.md` 的「真机自动化测试」一节原有 6 条约定，本次又踩到 3 条**新**的：

| # | 坑 | 现象 | 规避 |
|---|---|---|---|
| 7 | `mp.reLaunch()` / `navigateTo()` 到 **tabBar 页**不可靠 | 页面**停在上一个页面不动**，断言却"通过"了（测的是错页）→ **假通过** | 切 tabBar 页用**点 `.tab-item`** 或 `switchTab`；每步都断言 `currentPage().path` |
| 8 | `page.$$('goods-card')` 穿透不了自定义组件 | 恒返回 0（原约定 #2 已记）；本次又发现 `callMethod(fn, {currentTarget:{...}})` 的**嵌套参数会被序列化丢弃** → `current` 变 `undefined` | 点外层原生容器；callMethod 只传扁平参数 |
| 9 | **孤儿进程占用 auto-port** | IDE 主进程退出后端口仍被占（`netstat` 有、但 devtools 进程已不在），新实例「连上就断」或 `connect timeout` | 跑前 `netstat -ano \| grep <port>` 核查，用 `taskkill /F /PID` 清掉再启动 |

另外记录一条**环境注意事项**：本项目 IDE 环境存在「渲染进程被守护重启」现象
（`taskkill /F /IM WeChatAppEx.exe` 后立刻重生 9 个），清理不干净时不要反复重试，换静态校验更划算。

在 Git-Bash 下调用 Windows 原生命令**必须加 `MSYS_NO_PATHCONV=1`**，否则 `/F` `/IM` 这类参数
会被路径转换破坏（报「无效参数/选项 - '//PID'」）。
