## 二、发现的问题与修复

### 问题 1：`admin.adminLogs` 读取「未创建的集合」直接 500 🔴 真实 bug

```
admin.adminLogs → code=500
msg=collection.get:fail -502005 database collection not exists.
```

`admin_logs` 只在**产生过审计记录后**才会存在。写入侧都写了 `.catch(() => {})` 兜底，
但**读取侧没有兜底** → 直接抛 500。

**修复**：新增通用助手 `readSafe(run)`，集合不存在时降级为空列表（与写入侧的 `ensureAdd` 呼应），
并应用到 `adminLogs` 与 `pendingReports`（`reports` 集合同理可能不存在）。

### 问题 2：测试脚本自身的断言 bug（非应用问题，已修正）

「收藏 → 取消收藏」首次报失败，实际是**我的断言把「在收藏列表」与「不在收藏列表」混用了**。
排查后确认 `toggleFav` 行为完全正确（false → true → false）。已统一断言语义。

### 问题 3：撤回消息偶发未立即生效（非稳定 bug，已加校验+重试）

一次全量跑中 `chat.deleteMessage` 后消息仍可读到。用 `tools/diag_chat_delete.js` **隔离复现两次均正常**
（`code:0` → 列表变空 → 标记消失），判定为偶发；已给清理步骤加「校验 + 重试一次」，
重跑通过。**未发现可稳定复现的应用缺陷。**

## 三、本轮完善项（4 项）

### 完善 1：图片加载失败自动兜底 🖼️

背景：本项目此前反复出现图片裂图（`cloud://` 未解析 / 临时链接 10 分钟过期 / 空 `src`）。
`goods-card` 现在：
- `src` 由 JS 统一计算：无封面 → 占位图 `images/goods-cover-default.png`（此前回退成空串 → 报错留白）；
- 新增 `binderror="onImgErr"`：**网络失败 / 临时链接 403 过期时自动回退占位图**，不再留白。

### 完善 2：未读消息的 tabBar 角标 🔔

此前未读数**只在「消息」页内部显示**，用户在其他页面完全感知不到新消息。
新增 `app.setUnreadBadge(n)` / `app.refreshUnreadBadge()`：
- App `onShow` 与 openid 就绪后刷新；
- 「消息」页用**已有数据**同步（不额外发请求）；
- 进入/离开聊天页时刷新（读消息后角标应减少）；
- 数量 > 99 显示「99+」，为 0 时移除角标。

### 完善 3：全局错误钩子 🛡️

`app.js` 此前没有任何全局错误钩子，JS 异常会静默丢失。新增：
- `onError` / `onUnhandledRejection`：显式打日志（真机可在 vConsole 看到）；
- `onPageNotFound`：路径不存在时**兜底回首页**，避免用户停在白屏。

### 完善 4：首页「分享到朋友圈」📤

此前首页只有 `onShareAppMessage`（转发好友），`detail` 页两者都有。
现已为首页补上 `onShareTimeline`。

### 附带：全量页面巡检覆盖补齐

`tools/live_all_pages.js` 原本只覆盖 21 页，现已补上「我的订单 / 商品管理 / 用户管理 / 审核中心」，
达 25 页（聊天页需参数，已在流程中用真机渲染验证）。

### 7.1 发布页草稿自动保存（验证 4/4）

录入一条商品要填标题/描述/价格/分类/自提点 + 选好几张图，中途切走、接电话、杀进程会全丢。

- 新增 `cm_publish_draft_v1`：表单各输入、`chooseImage`、`removeImage`、`onHide` 均落盘；
  `onShow` 首次进入恢复一次（避免覆盖正在填的内容）；
- 恢复时弹「**继续编辑 / 清空重填**」，给丢弃草稿的出口；
- 发布成功 `resetForm()` 时清除；**编辑已有商品时不写草稿**（避免与编辑内容混淆）。
- 顺手修：`resetForm()` 的 `form` 缺 `type` 字段 → 重置后「出售/求购」切换态异常。

### 7.2 我的收藏快捷取消收藏（验证 6/6）

此前必须进商品详情才能取消。现在卡片下有「取消收藏」按钮，**乐观更新**（先本地移除，失败回滚）。
`.btn-mini` 样式原本只定义在 `pages/sold/sold.wxss`（页面私有），已**提升到 `app.wxss`** 供复用。

### 7.3 图片上传前统一转 JPEG（验证 5/5）

根因：`wx.compressImage` 的 quality **只对 JPG 生效**，PNG 原样保留 → 选截图就是 4~6MB。

- `_compress` 后若仍 > 800KB → 离屏 canvas 重绘导出 JPEG（长边 1280 / q0.85，先铺白底防透明区变黑）；
- ⚠️ 第一版有缺陷：实测**高频噪点图转 JPEG 反而更大**（100KB → 294KB）。
  已改为**「取更小者」**——只有 JPEG 确实更小才采用，**保证该优化只会更好、绝不劣化**；
- 实测（最不利于 JPEG 的随机噪点样本）：**3215 KB → 559 KB**。

### 7.4 管理后台审计日志入口（验证 5/5，并挖出更深 bug）

管理后台新增可展开的「操作日志」卡，action 做了中文化（查看用户敏感资料 / 商品审核 / 封禁用户 …）。

**更重要的发现 🔴**：`admin_logs` 集合不存在，而 6 处写入都是
`db.collection('admin_logs').add({...}).catch(() => {})` → `-502005` **被静默吞掉**，
**审计记录其实一条都没落库**（接口全部返回成功，极难发现）。

已全部改为 `ensureAdd('admin_logs', {...}).catch(() => {})`（先建集合再重试）。
至此读取侧（`readSafe`）与写入侧（`ensureAdd`）都补齐了。
