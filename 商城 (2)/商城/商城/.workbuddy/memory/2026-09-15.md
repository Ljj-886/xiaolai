## 求购模块专项检查与修复（3 个真实问题）

**背景**：用户要求「求购模块去检查一下有没有问题」。系统排查 + 真机验证后发现 3 个真实缺陷。

### 问题 1（严重）云开发：字段级 `_.or([{字段:值},...])` 嵌套写法**完全不生效**

`goods.list` / `user.myGoods` 里判断「出售」的写法是：
```js
where.type = _.or([{ type: 'sell' }, { type: _.exists(false) }, { type: null }]);
```
**实测该写法被云开发静默忽略**（不报错），导致「闲置」列表混入求购商品 —— 首页 sell tab 会冒出求购。
探测结论（`goods` 集合 8 条 onSale）：

| 写法 | 结果 |
|---|---|
| `_.or([{type:'sell'},{type:_.exists(false)},{type:null}])` | ❌ n=6，**含 want**（失效） |
| `_.neq('want')` | ✅ n=5，无 want，且保留 3 条历史无 type 商品 |
| `type:'sell'` | ⚠️ n=4，会漏掉历史无 type 商品 |

**修复**：统一改 `where.type = _.neq('want')`（语义等价且实测生效）。已改 `cloudfunctions/goods/index.js`（list）+ `cloudfunctions/user/index.js`（myGoods）并部署。
> 注：同文件 class campus 的 `_.or([{campus:x},...])` 是同一写法，但当前库里没有 campus 缺失的老文档，**无法验证**，故按「不擅自改未验证代码」原则保留原样（已实测 A/B/C 三种写法结果一致）。

### 问题 2 无图求购详情页显示「1/0」+ 大片白块
求购允许 0 图（服务端 `isWant` 时 images 可空），但 `detail.wxml` 的 swiper 无条件渲染 → 计数器 `{{swiperCurrent+1}}/{{item.images.length}}` 显示 **1/0**，hero 区留白。
**修复**：`images.length` 为 0 时不渲染 swiper/计数器，改渲染求购专用占位区 `.hero-want`（🔍 + 「求购商品 · 暂无图片」），样式在 `detail.wxss`。

## 全项目审计 → 修复 P0：多校隔离静默失效（`_.or` 又踩一次同一个坑）

**背景**：用户问「还有哪里需要优化的」。做了一轮系统性审计（两个并行 Explore：
一个查前端 WXML/JS，一个查 9 个云函数的权限/校验/健壮性），并对最严重的一条**做了对照实验验证**。

### ★ P0（已修 + 已实测验证）：`where.campus = _.or([...])` 静默失效，多校隔离形同虚设

`cloudfunctions/goods/index.js` 的 `list()` 里，多校隔离写成了：
```js
where.campus = _.or([{ campus: mySchool }, { campus: _.in(['', null]) }, { campus: _.exists(false) }]);
```
**这正是同文件 323 行注释刚警告过的坑**（`where.type = _.or([...])` 静默失效）——
「把 `_.or` 赋值给某个字段」云开发会**忽略整个条件且不报错**。

**决定性实验**（`tools/_probe_campus_or2.js`）：goods 集合 onSale 共 6 条本校 + **临时插入 1 条外校**
（北京大学），调不同写法比对，测完立即删除测试数据：

| 写法 | 结果 | 隔离外校? |
|---|---|---|
| `where.campus = _.or([...])`（**原代码**） | **7 条，含外校** | ❌ **失效** |
| `_.and([where, _.or([...])])`（顶层） | 6 条 | ✅ |
| `where.campus = mySchool`（等值） | 6 条 | ✅ |

> 复现要点：**只用现有数据测不出来**（库里 6 条 onSale 全是「清华大学」，过滤失效与生效结果相同），
> 必须**临时插入一条异校数据**才能定性 —— 这是本次审计最关键的方法论。

**修复**（`goods/index.js`，已部署 16.0 KB）：
- 新增 `let campusOr = null`，学校过滤时把 `_.or([...])` 存进 `campusOr` 而**不赋值给 where.campus**；
- 组装查询时统一把「或」条件提成顶层：`ors = [campusOr?, kwOr?]`，最后
  `_.and([where, ...ors])` 组合 —— 顺带把原来硬编码的 `_.and([where, _.or([{title},{desc}])])`
  也统一进这个数组，避免以后再加条件时又踩坑；
- 在代码里留了**实测数据注释**（7 条含外校 vs 6 条不含），并把结论升格为通则：
  **凡「或」条件一律提顶层用 `_.or` / `_.and` 组合，绝不赋值给字段。**

**验证（`tools/verify_campus_isolation.js`，6/6 通过）**：
- `listHasOther: false`、`listLen: 6`（对比修复前的 7）→ **外校商品不再泄露** ✓
- 带关键词时同样不串校；关键词搜索本身仍正常（kw=`11` → 3 条全匹配）；分类筛选正常（1 条）；
- 首页渲染回归 **0 错误 0 警告**（5 条商品）。

## 一、P0 数据正确性（最严重）

**1. 超卖 —— `order.create` 先读校验、后无条件写**
- 原码：`gRes.get()` 校验 `status==='onSale'` → 建单 → `doc().update({status:'reserved'}).catch(()=>{})`。
- 两个买家并发下单时**都读到 onSale、都建单成功** → 同一商品出现多个有效订单；且写入失败被吞，
  商品可能仍停在 `onSale` 被反复下单。
- 修法：**原子抢占** —— `where({_id, status:'onSale'}).update({status:'reserved'})`，
  `stats.updated !== 1` 直接返 409「手慢了…」；建单失败则回滚商品回 onSale（否则永久卡 reserved）。

**2. 计数重复 —— `order.complete` 无幂等**
- 原码：get 校验 `status in [meeting,paid]` → 无条件 update completed → `_.inc(1)` 双方计数。
- 买卖双方同点「完成」→ 两人都通过校验 → `soldCount`/`boughtCount` **各 +2**。
- 修法：条件更新 `where({_id, status: _.in(['meeting','paid'])})`，只有 `updated===1` 的那次才推进
  商品 sold 与计数 → 天然幂等。
- 顺带：`sellerConfirm` / `buyerCancel` / `sellerCancel` 同类竞态一并条件化。

**3. 新增 `releaseGoods(goodsId)` helper**：释放商品回在售时带 `status:'reserved'` 条件 ——
原来的无条件写 `onSale` 会把「订单等待期间已被管理员下架/禁售」的商品**复活上架**。

## 六、方法论沉淀（本轮新增，重要）

**单账号如何测并发？** 本机只有一个账号，`order.create` 又禁止购买自己的商品，无法真实模拟两个买家。
解法：用**客户端 `wx.cloud.database()`**（安全规则允许本环境写入）**直接构造测试数据** ——
插入一条 `status:'onSale'` 的测试商品、一条 `sellerId=我 / buyerId=假 / status:'meeting'` 的测试订单，
然后 `Promise.all` 并发调用真实云函数，断言「恰好 1 次成功 + 计数只 +1」，最后自清理。
`tools/verify_campus_isolation.js` 的「插异值」思路在此升级为「**插中间态**」。

**`checkTimeout` 节流测试会抖**：节流是**进程内**时间锁，两次调用可能落在不同云函数实例上，
于是都返回 `throttled:false`（也正确）。判 PASS 要看「同实例时第二次必被拦」，
不能断言「第二次一定被拦」—— 本次首跑 14/15、重跑 15/15 即为此现象。**改前先确认不是回归**。

**automator 脚本必须 `process.exit()`**：`miniprogram-automator` 会保持 ws 连接，
不显式退出则进程永不结束（表现为「日志已写完但 shell 挂 8 分钟以上」）。
本轮给 `verify_hardening.js` / `verify_campus_isolation.js` 都补上了。
